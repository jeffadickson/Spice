# Overnight endurance campaign

`make endurance` defaults to five hours; the explicit duration may be configured up to 24 hours. The supervisor allocates at most half the remaining budget to pinned cargo-mutants
and Stryker.NET first, then uses remaining time for Proptest-generated byte/Unicode
parser inputs, sparse layouts/products, analytical dividers, diode derivatives and
near-zero current checks. The library owns generation, shrinking and persistence.
Custom selected mutations require -SelectedRegressions and receive at most a
quarter of the post-framework remainder, capped at 15 minutes. Framework baseline/infrastructure
failures stop the campaign; survivors remain findings and deadline-limited framework
work remains partial. This is seeded fuzz/property testing, not coverage-guided
libFuzzer. Neither a bounded shard nor the 22 targeted checks are exhaustive.

Read [framework mutation setup and reports](mutation-frameworks.md) before the
first run. The default launcher verifies both tools; use make mutation-tools to
install pinned versions. SkipMutation explicitly skips supplemental and generated
mutations. Short smoke budgets should use that switch; cold compilation and
framework discovery may consume a small budget before any mutants are tested.

Commands from the repository root:

```powershell
$checkout=(Get-Location).Path
if(-not(Test-Path -LiteralPath $checkout -PathType Container)){throw 'Checkout missing'}
make endurance                       # default 300-minute budget
make endurance MINUTES=30            # bounded shorter campaign
make endurance-smoke                 # 3 minutes, seed 1, mutations explicitly skipped
./scripts/Run-Endurance.ps1 -Minutes 300 -Background
```

On this host GNU make is at `C:/dev/tools/msys64/usr/bin/make.exe` if it is not
on PATH. The PowerShell entry point needs no make installation. It verifies the
pinned compiler and can recover the existing sibling portable Rust environment.
A cold build can consume a short smoke budget; that is recorded as incomplete,
not passing. Use a larger budget to warm the cache when necessary.

The worker takes an exclusive lock, preserves a source archive and hashes under
`work/endurance/<UTC-run-id>/repo`, and builds in a separate reusable workspace.
The source archive, source commit/dirty state, compiler/.NET versions and initial
seed identify the tested code. Snapshot acquisition rejects source edits racing
its reads. Later source edits do not affect the run. Shared build caches under
`target/` avoid rebuilding dependencies every night. Generated artifacts stay
ignored; campaigns do not update tracked qualification summaries or source.

`summary.json` is atomically refreshed after each completed batch. Counts cover
completed batches only. `pending_seed` identifies interrupted or failing work.
Budget exhaustion is distinct from success; mutation skip/timeout is explicit.
Build/mutation/failing-batch logs are retained with a 1 MiB-per-stream text limit
and truncation marker. Compiler and test concurrency is limited to two. Each property
batch has a 60-second watchdog; cold builds and the mutation phase have their own
caps inside the total deadline. Mutation tests allow up to 900 seconds each in
this workflow, while ordinary Mutation.cs runs keep the 180-second default.

Failures retain batch logs, the pending seed and the library's persisted regression
file under failure/. Cases count requested successful generated cases in completed
batches; extra persisted replays and shrink attempts are excluded. property_library,
property_count, property_cases_per_method and case_count_kind identify that meaning.
Old summaries without these fields retain their legacy seeded-case meaning.
For replay, build the archived source and run:

```powershell
$checkout=(Get-Location).Path
if(-not(Test-Path -LiteralPath $checkout -PathType Container)){throw 'Checkout missing'}
$env:PROPTEST_RNG_SEED='<decimal pending seed>'
$env:PROPTEST_CASES='128'
cargo test --locked --test property_campaign -- --nocapture
```

The replay seed regenerates the library batch; preserve the persisted regression
file and printed minimized input too. Historical legacy runs use SPICE_CAMPAIGN_SEED
and tests/endurance.rs as recorded in their source archives, rather than the new
count semantics. The property suite also runs in ordinary cargo test with its
bounded checkpoint configuration. Case sizes and generated numeric
domains are bounded. No OS-wide memory cap, coverage guidance or forced-termination
cleanup guarantee is claimed. A forcibly terminated supervisor leaves an unfinished
summary; inspect for remaining children before restarting. Archives/caches need
periodic disk-space review; no automatic deletion of failure evidence is configured.

For automated clone/setup/test/result-branch upload on another machine, see [the remote-run guide](remote-runs.md).

The requested local schedule is midnight to approximately 5 a.m. in
America/Los_Angeles, with a morning results check. The machine must be available
for local execution. This five-hour duration is configured, not yet qualified by
a completed five-hour run. Early defects/timeouts stop the campaign for review.
