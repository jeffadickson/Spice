Semantic frontend
=================

Recognition is generated by ANTLR 4.13.1. ``DeckParser.Parse`` never opens include
files, evaluates parameters, executes controls or invokes a simulator.

Three explicit subsequent operations are available:

* ``ResourceResolver.Resolve`` loads permitted UTF-8 resources under budgets and
  returns atomic expanded text plus original-file source segments.
* ``InstanceBinder.Bind`` binds observed X/model references and ordered ports,
  retaining missing, ambiguous, deferred, invalid and unsupported outcomes.
* ``ParameterEvaluator.Evaluate`` and ``ForInstance`` evaluate finite lexical
  parameter profiles with catalog-branded per-instance environments.

Binding is symbolic. The bounded R/V/I DC bridge below flattens active hierarchy
into typed requests; general model/global translation remains open. Default
corpus observation does not load resources; explicit roots enable rebinding.
Neither corpus mode runs numerical simulation.
The matched ngspice profiles are named finite checks, not full SPICE conformance.

Refer to the repository's ``docs/semantic-frontend.md`` for exact supported
operators, numeric suffixes, default/override policies, resource limits, source
mapping and reproducible commands. All new generated outputs on the current
Windows host belong on E:. No native Linux, GPU or production qualification is
implied; the exFAT artifact volume cannot qualify symbolic-link creation.

Operating-point bridge
----------------------

``Simulator.Frontend`` connects the generated syntax/catalog to the existing
``Simulator.Client`` request API and Rust engine. Resolve resources explicitly,
parse with ``collectDeclarations: true``, and call
``OperatingPointBridge.Lower(syntax, backend: "faer")``. Check ``Success`` before
passing ``Request`` to ``SimulationClient.RunAsync``. ``RootNodes`` maps original
root node spellings to compact wire names; ``Origins`` retains element source
ranges and hierarchical paths. Resource source maps remain with the resolver.

The initial bridge covers constant DC resistors and independent voltage/current
sources, including parameterized subcircuits. It refuses unsupported active cards
atomically. It requires a globally definite declaration catalog even for unused
conditional/resource declarations. Private nodes are isolated per expansion.
Default budgets are depth 32, 128 frames including root, 1024 elements and 128
nodes. Backend request keys are ``lu``, ``qr`` and ``faer``.

Syntax acceptance, resource resolution, semantic binding, request lowering and
numerical agreement are separate outcomes. The opt-in corpus ``-ResourceRoots``
profile records the first three and never simulates samples. The bridge does not
yet expose model devices, waveform sources or AC/transient from text. Those
analyses remain available through the existing engine's supported API contracts.

Resource policy refinements
---------------------------

``ResourcePolicy.ParsingLimits`` selects the immutable recognition profile for
each root/fragment. Fragment title prefix input counts against those limits.
Corpus resource and expanded parsing use the explicitly declared campaign
profile; interactive defaults remain unchanged. ``.csparam`` is a control-vector
export rather than a resource branch selector, so its presence alone does not
refuse an unconditional include. Resolution still does not evaluate it, and real
conditional resources remain refused. Failed recognition retains at most three
physical source diagnostics in ``ResourceDiagnostic.SyntaxDiagnostics``.

Voltage-reference continuation: generated expression-mode recognition treats
one/two v(...) arguments as node spellings, including signs, bus/path punctuation,
quoted names and physical continuations before or inside the opener. Ordinary
arithmetic remains separate, source ranges are preserved, and the composite
opener counts toward the existing group budget. Parameter evaluation does not
resolve signal references. Native syntax probes and numeric agreement are
reported separately; a scaled LIMIT control remains numerically unqualified.

Controlled-source TABLE and numerical reporting
-----------------------------------------------

The generated grammar recognizes the selected E/G ``TABLE {expression}`` tail,
optional equals, and continued coordinate pairs with optional comma separators.
Once the braced TABLE form is selected, odd coordinate counts and malformed
controlling expressions are syntax errors. Coordinate commas/parentheses are
local separators, including legacy unmatched wrappers, as in native ngspice. TABLE is contextual: a T device or ordinary node named ``table``
retains its existing spelling. The ``source_form:table`` observation carries the
original physical tail range. Recognition adds no Rust TABLE interpolation.

Each completed gap checkpoint reruns the numerical corpus matrix and named
ngspice regressions. Lead with unique fully compared and partially compared
files, mismatches, refusals and unfinished inputs. Keep the older numerical
importer and generated frontend bridge identified separately. Root acceptance
and resolved libraries never count as numerical passes; named fixtures and
multiple solvers do not inflate corpus file counts.

``CorpusCommand --output`` places both bounded reports and raw child artifacts
beneath the selected directory. A benchmark ``--report`` path also locates raw
child artifacts alongside that report. Use an existing unique E: campaign parent
on this host, plus ``--artifacts-path`` for managed builds and TEMP/TMP for child
temporary data. Repeated process timing is distinct from numerical accuracy;
a debug engine versus a separately built ngspice is not a release speed ranking.

Explicit selected static operating point
----------------------------------------

``OperatingPointBridge.Lower`` retains its strict R/V/I contract. Call
``OperatingPointSelection.Select`` to request a separate static operating point
for ideal R/C/L and independent constant V/I declarations. The result exposes
``Prepared`` and immutable ``Omissions`` with scope, original range, generated
leading token and reason. Capacitors/inductors retain positive SI values; the
existing Rust operating-point equations supply steady open/short behavior.
Original analyses, input controls and a bounded set of read-only observations
are explicitly excluded. This is not execution of those original programs.
Unqualified directives remain refused, including extensions in unused bodies
that might have global physical effects. Failure publishes no partial plan.

``scripts/Run-FrontendCorpus.cs`` executes eligible original corpus files through
that operation and the public Client wire API on LU/Faer. Its independent native
oracle uses expanded original source with only recorded instruction ranges
blanked; circuit values are not reconstructed from lowered requests. Seventeen-
digit print probes avoid the observed six-digit echo interpolation loss. Root
voltage agreement uses absolute 1e-9 V plus relative 1e-8. Solves without exposed
root voltages remain unqualified, not mismatches or passes. Response identity,
finite samples, unique signals and required units are checked before comparison.
Synthetic fault fixtures test that malformed/mismatching data never pass; they
are kept separate from actual Rust/ngspice qualification counts.

Source clauses and selected AC probes
--------------------------------------------------

The generated frontend now retains independent DC and AC source values. Selected DC
executes35 corpus files;34 match native root voltages and one has no root reference.
Seven files also match explicit1/100/1000Hz complex AC probes on both CPU providers.
This is selected-analysis evidence, not original sweep/control/transient execution.
Only qualified reporting flags acct/noacct/noinit are omitted; numerical options remain explicit gaps.
See the `results report <https://github.com/jeffadickson/Spice/blob/main/docs/corpus-source-execution-results.md>`_
and `runtime backlog <https://github.com/jeffadickson/Spice/issues/21>`_.

PSpice smooth switch profile
----------------------------

Selected static preparation supports ``S`` instances bound to an explicit
``VSWITCH(RON=... ROFF=... VON=... VOFF=...)`` model. Generated model metadata
and retained lexical parameter snapshots supply the four values; no second
lexer or source-text card splitting is used. The CLI accepts
``selected-static-op`` and retains ``selected-linear-op`` as a legacy alias.
The result profile is named ``generated_frontend_selected_static_op``.

The Rust model uses cubic smoothstep in log resistance. Output conductance and
control-voltage transconductance use the same signed derivatives in Newton and
small-signal AC. The latter linearizes about the converged DC bias. The control
port is ideal high impedance; ngspice pswitch's default finite input loading is
not reproduced. Native comparisons use ideal control voltage sources and
compare voltage outputs. Hysteretic ``SW``, general XSPICE, temperature/noise
and broad transient qualification remain outside this profile.

Requirements ``SEM-VSWITCH-001`` and ``SEM-VSWITCH-002`` retain the exact bounds
and verification scope. ``compat/ngspice/bug883-vswitch.cir`` and its library
preserve the motivating public circuit's topology and values. For original
native include-based execution use ``ngspice -n -D ngbehavior=ps -b``; expanded
oracle decks explicitly use ``psa`` so whole-deck conversion occurs before
parsing. Selected frontend probes are distinct from executing the original
control language or sweep program.

Explicit nonlinear transient bias
----------------------------------------

``TransientConfiguration.InitialNewton`` controls only nonlinear time-zero bias.
The selected frontend emits bounded source continuation for nonlinear transients;
linear requests retain their previous wire shape. The policy cannot accompany an
explicit initial state or a fixed Gmin shunt. Continuation requires actual
time-zero source RHS to equal nominal DC; direct initialization still uses the
actual RHS. The provider, later Newton settings and integration budgets are
preserved. ``IntegrationInfo.InitialNewton`` retains actual bias work and recovery
stages. A failure remains a failure; another provider is never silently selected.

``examples/transient-initial-bias.request.json`` demonstrates a 1 microampere
current-driven ideal diode. Its independent inverse-Shockley bias is
0.5356964219 V with IS=1e-15 A and Vt=0.02585 V. The example completes on faer;
this finite constitutive check does not qualify full semiconductor families.
The original BJT amplifier now completes 200 steps on faer with this explicit
policy, while LU still refuses later componentwise refinement. Native full
waveform agreement remains open.

Grammar implementation map
----------------------------------------

The generated parser's complete production list is joined with reviewed
extraction, preparation and execution assessments. Unassessed productions remain
visible. Concrete historical control headings are listed separately, exposing
missing command families behind generic syntax. Each association retains stable
requirements, source/evidence paths and explicit limits. See the repository's
``docs/grammar-implementation.md`` and generated HTML/JSON inventories.

Simple local let/define/unlet declarations after the final analysis may be
retained as explicit unexecuted postprocessing. Root observable/axis replacement,
nonlocal deletion and declarations before a later analysis refuse atomically.
The retained expressions are not evaluated. Individual requested-analysis
qualification remains separate from full control-program parity.
